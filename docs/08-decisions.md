# 8. Журнал технических решений (ADR)

> **Версия:** v4 · **Дата:** 2026-10-13 · **Статус:** действующий

ADR (Architecture Decision Record) — запись о принятом решении: что выбрали, из каких вариантов и почему. Решения не удаляются; если решение пересмотрено, создаётся новая запись, а старая получает статус «заменено ADR-NNN».

---

## ADR-001. Чистый образ Windows вместо модифицированной сборки

- **Дата:** 2026-10-08 · **Статус:** принято
- **Контекст:** на внешний SSD была установлена «lite»-сборка Windows 11 стороннего автора. В ней отсутствовали Microsoft Store и winget.
- **Варианты:** продолжить на сборке и чинить по ходу; переустановить с официального образа.
- **Решение:** переустановка с официального ISO Microsoft, редакция Pro.
- **Причины:** на машине будут храниться ключи и токены доступа ко всей инфраструктуре — изменения неизвестного автора недопустимы; вырезанные компоненты мешают работе; на момент решения система ещё не была настроена.

## ADR-002. Windows + WSL2 как основа рабочей станции

- **Дата:** 2026-10-08 · **Статус:** принято
- **Решение:** инструменты DevOps запускаются в WSL2 (Ubuntu), редактор и графические программы — в Windows.
- **Причины:** большинство инструментов DevOps родом из Linux; Ansible не поддерживает Windows как управляющую машину; навык работы в Linux необходим.

## ADR-003. Ubuntu 24.04 LTS в WSL

- **Дата:** 2026-10-08 · **Статус:** принято
- **Варианты:** Ubuntu 26.04 LTS, Ubuntu 24.04 LTS, Debian.
- **Решение:** Ubuntu 24.04 LTS.
- **Причины:** наибольший объём документации и инструкций; гарантированная поддержка сторонних репозиториев (Docker, HashiCorp); поддержка до 2029 года. Другие дистрибутивы можно установить параллельно.

## ADR-004. VS Code как основной редактор

- **Дата:** 2026-10-08 · **Статус:** принято
- **Причины:** интеграция с WSL и SSH, поддержка Git, YAML, Terraform, Ansible, Kubernetes, Claude Code.

## ADR-005. Отдельные SSH-ключи для Windows и WSL

- **Дата:** 2026-10-08 · **Статус:** принято
- **Причины:** при компрометации одного окружения отзывается только его ключ; на GitHub видно происхождение каждого ключа.

## ADR-006. Документация как код (Markdown в Git)

- **Дата:** 2026-10-08 · **Статус:** принято
- **Варианты:** Word/Google Docs; вики; Markdown-файлы в репозитории.
- **Решение:** Markdown в Git-репозитории, единая версия документации (v1, v2…), журнал изменений, Git-теги.
- **Причины:** документация лежит рядом с кодом и меняется вместе с ним; полная история изменений; читается на GitHub, в VS Code и ИИ-ассистентами; практика docs-as-code используется в индустрии.

## ADR-007. Репозиторий Proxmox pve-no-subscription

- **Дата:** 2026-10-09 · **Статус:** принято
- **Контекст:** были подключены только enterprise-репозитории, требующие платной подписки; сервер не получал обновления Proxmox.
- **Варианты:** купить подписку; подключить no-subscription; не обновлять.
- **Решение:** отключить enterprise-репозитории (pve и ceph-squid), подключить `pve-no-subscription` и `ceph-squid no-subscription`.
- **Причины:** учебная среда, подписка не нужна; no-subscription — стандартный выбор для homelab. Отказ от обновлений недопустим по соображениям безопасности.

## ADR-008. SSH: вход только по ключам, настройки в drop-in файле

- **Дата:** 2026-10-09 · **Статус:** принято
- **Решение:** `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin prohibit-password` в отдельном файле `/etc/ssh/sshd_config.d/10-hardening.conf`.
- **Причины:** исключает подбор пароля; ключи ed25519 с passphrase уже используются. Drop-in файл не конфликтует с обновлениями пакета `openssh-server`, изменения легко найти и откатить.
- **Последствия:** вход по SSH возможен только с рабочей станции (Windows или WSL); резервный доступ — физическая консоль и Shell веб-интерфейса.

## ADR-009. Многоуровневая защита веб-интерфейса: Cloudflare Access + TOTP

- **Дата:** 2026-10-09 · **Статус:** принято
- **Контекст:** веб-интерфейс Proxmox был опубликован в интернет через туннель и защищён только паролем `root`.
- **Варианты:** закрыть туннель и пользоваться только VPN; Cloudflare Access; только 2FA в Proxmox.
- **Решение:** Cloudflare Access (политика «только почта владельца», одноразовый код) + TOTP в Proxmox для `root@pam` + коды восстановления.
- **Причины:** Access отсекает посторонних до того, как запрос дойдёт до сервера; TOTP защищает и при доступе из локальной сети, где Access не действует. Принцип эшелонированной защиты (defense in depth).

## ADR-010. Удаление неиспользуемых VM, сохранение одной тестовой Windows

- **Дата:** 2026-10-09 · **Статус:** принято
- **Контекст:** на сервере три выключенные VM с Windows 10, созданные до проекта, каждой выделено 12 vCPU и 8 ГБ RAM.
- **Решение:** удалить VM 101 и 102 вместе с дисками; оставить VM 100 (`wVM`) как тестовую — единственную с оптимальной конфигурацией (VirtIO, q35, `cpu: host`); уменьшить её до 1×4 vCPU и 4 ГБ RAM.
- **Причины:** освобождение ресурсов под кластер Kubernetes; ценных данных на VM не было.

## ADR-011. Запуск cloudflared после network-online.target

- **Дата:** 2026-10-09 · **Статус:** принято
- **Решение:** drop-in `/etc/systemd/system/cloudflared.service.d/override.conf` с `Wants=`/`After=network-online.target`.
- **Причины:** `network.target` не гарантирует, что сеть уже настроена; туннель должен стартовать после появления рабочей сети. Основной unit-файл не изменяется.

## ADR-012. Менеджер паролей KeePassXC

- **Дата:** 2026-10-13 · **Статус:** принято
- **Варианты:** Bitwarden (облачный, синхронизация «из коробки»); KeePassXC (локальный зашифрованный файл).
- **Решение:** KeePassXC, база `homelab.kdbx`; TOTP — в отдельном приложении на телефоне, в базе — только коды восстановления.
- **Причины:** владелец уже использует KeePass на работе; полный контроль над файлом базы; формат `.kdbx` открывается и KeePass 2, и мобильными клиентами.
- **Последствия:** резервное копирование и синхронизацию базы владелец обеспечивает сам (см. [07](07-backups.md)).
