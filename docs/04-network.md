# 4. Сеть

> **Версия:** v3 · **Дата:** 2026-10-09 · **Статус:** действующий

## 4.1. Общие сведения

| Параметр | Значение |
|---|---|
| Подключение к интернету | Через домашний роутер |
| Внешний IP | **Серый** (за NAT провайдера), входящие подключения из интернета напрямую невозможны |
| Локальная подсеть | `192.168.1.0/24` |
| Шлюз (роутер) | `192.168.1.1` |
| DNS сервера | `/etc/resolv.conf` (проверено, разрешение имён работает) |

## 4.2. Сетевая конфигурация сервера

| Интерфейс | Тип | Адрес | Назначение |
|---|---|---|---|
| `enp6s0` | Физический (Realtek RTL8111) | — (manual) | Порт сервера, входит в мост `vmbr0` |
| `vmbr0` | Linux bridge | **192.168.1.100/24**, статический | Адрес хоста; через мост выходят в сеть все VM |

Действующий `/etc/network/interfaces` (с 2026-10-09):

```
auto lo
iface lo inet loopback

auto enp6s0
iface enp6s0 inet manual

auto vmbr0
iface vmbr0 inet static
        address 192.168.1.100/24
        gateway 192.168.1.1
        bridge-ports enp6s0
        bridge-stp off
        bridge-fd 0

source /etc/network/interfaces.d/*
```

Применение изменений без перезагрузки: `ifquery -a` (проверка) → `ifreload -a`. Перед правкой — резервная копия файла; правку сети выполнять с физической консоли.

### 4.2.1. История: проблема P-01 (закрыта)

До 2026-10-09 файл содержал опечатку `auto vmdr0` и адрес `.101`: мост `vmbr0` не поднимался при загрузке, сеть приходилось поднимать вручную. Исправлено 2026-10-09, проверено перезагрузкой. Резервная копия старого файла: `/etc/network/interfaces.bak-2026-10-09`.

## 4.4. Удалённый доступ — Cloudflare Tunnel и Access

| Параметр | Значение |
|---|---|
| Туннель | `proxmox-tunnel` (локально управляемый, конфигурация в файле) |
| Где работает `cloudflared` | Непосредственно на хосте Proxmox |
| Конфигурация | `/etc/cloudflared/config.yml` |
| Учётные данные | `/root/.cloudflared/<tunnel-id>.json` — **секрет** |
| Протокол / площадки | QUIC; соединения с площадками Cloudflare `ala02` (Алматы), `waw04/05` (Варшава) |

Правила `ingress`:

| Hostname | Куда ведёт | Параметры |
|---|---|---|
| `proxmox.<домен>` | `https://localhost:8006` (веб-интерфейс Proxmox) | `noTLSVerify: true` — Proxmox использует самоподписанный сертификат |
| *(всё остальное)* | `http_status:404` | Правило по умолчанию |

> Имя домена в публичном репозитории не указывается — минимизация информации об инфраструктуре.

### 4.4.1. Cloudflare Access (с 2026-10-09)

| Параметр | Значение |
|---|---|
| Тип приложения | Self-hosted, Public DNS |
| Приложение | `Proxmox` → `proxmox.<домен>` (весь сайт, без указания пути) |
| Политика | `Only me` — Allow, Include: Emails = почта владельца |
| Способ входа | One-time PIN (код на почту) |
| Длительность сессии | 24 часа |
| Cookie | HTTP Only включён |
| Проверено | 2026-10-09: разрешённая почта — доступ есть; посторонняя почта — доступа нет |

Цепочка доступа снаружи: **браузер → Cloudflare Access (код на почту) → туннель → `cloudflared` → Proxmox (пароль + TOTP)**.

## 4.5. Способы доступа к серверу

| Ситуация | Способ | Защита |
|---|---|---|
| Дома, веб-интерфейс | `https://192.168.1.100:8006` | Пароль + TOTP |
| Дома, SSH | `ssh pve` (`root@192.168.1.100`) | Только SSH-ключ |
| Вне дома, веб-интерфейс | `https://proxmox.<домен>` | Cloudflare Access + пароль + TOTP |
| Вне дома, SSH | ⏳ не настроено (варианты: Cloudflare Access for SSH, Tailscale) | — |
| Авария | Физическая консоль сервера | Пароль `root` |

|---|---|---|---|
| 22 | TCP | SSH | Локальная сеть |
| 8006 | TCP | Веб-интерфейс Proxmox | Локальная сеть, через туннель |
